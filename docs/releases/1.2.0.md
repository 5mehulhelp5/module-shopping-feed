# Mage-OS Shopping Feed 1.2.0

**Release candidate, not yet published.** Version 1.1.0 remains the current stable release. This document is the source for the draft 1.2.0 release notes. See the [preparation record](../reviews/2026-10-03-release-1.2.0-preparation.md) for publication gates.

Version 1.2.0 replaces New/Edit Feed and Test Feed with Magento UI Component forms, adds five catalog presets, and corrects stock selection, configurable Local Inventory, store-scoped frontend settings, and existing-feed currency handling. Existing feed data, routes, and permissions remain in place. Stores with custom editor integrations or product-adapter subclasses need the upgrade review below.

## Admin forms and Nebula

The editor uses collapsible sections, DynamicRows, declarative field dependencies, and explicit mapping order. Categories, directive parameters, promotion dates, schedules, uploads, and product previews use the shared form data and persistence contract. Save, reopen, unchanged save, and generated-output checks cover all eight presets on Magento Open Source 2.4.8 and 2.4.9 and Mage-OS 3.5.0.

The forms preserve structured and null parameters, empty collections, zero values, literal text, category identity, and all four promotion dates. Existing feeds whose saved currency is blank display their effective generation currency, so an unchanged save does not substitute a different store default. Preview errors are recoverable, and grid mutation controls follow the administrator's permissions.

This removes the active editor's dependence on legacy PHP form widgets and custom dependency handling. Nebula can share that form contract in future integration work. The optional Nebula grid, standard-theme editor fallback, and menu handling remain. The migration does not remove most of the approximately 575 lines counted in the earlier Nebula integration, roughly 495 of which belong to the grid. Native Nebula UI Bridge rendering remains unverified. No Nebula package is required; the final local acceptance used Magento/backend with Nebula disabled. See the [editor guide](../ui-component-editor.md#nebula-support).

## New catalog presets

| Preset | Output and scope |
| --- | --- |
| [Meta Catalog](../wiki/Meta-Catalog.md) | Quoted UTF-8 TSV, Meta availability values, currency prices, variant grouping, and required-field validation |
| [Microsoft Merchant Center](../wiki/Microsoft-Merchant-Center.md) | Tab-delimited TXT, Microsoft availability and sale-price formatting, identifiers, and variant validation |
| [TikTok Catalog](../wiki/TikTok-Catalog.md) | Quoted UTF-8 CSV with `sku_id`, native availability values, additional images, and variant checks |
| [Pinterest Catalog](../wiki/Pinterest-Catalog.md) | Quoted UTF-8 TSV with native availability, category paths, field limits, and configurable grouping |
| [OpenAI / ChatGPT, Google-compatible beta](../wiki/OpenAI-ChatGPT.md) | TSV discovery profile with identifier, date, price, and variant checks; requires profile confirmation during onboarding |

Generic, Google Shopping, and Google Local Inventory remain available. Google Promotions remains a companion of Google Shopping, not a separate New Feed preset. The five new presets passed local generation and validation checks; external provider ingestion is unverified. The OpenAI preset does not establish account access or checkout support. Existing saved maps are not rewritten.

## Generation and security corrections

* Feed stock settings take precedence over storefront out-of-stock hiding for simple, configurable, grouped, and bundle products.
* Configurable Local Inventory parents derive linked sources from their children and require an enabled child source item at the same source before reporting availability.
* Microdata, native price-schema suppression, Google Ads event enablement, and the optional destination honor website and store-view overrides.
* Escaping, request validation, grid output, malformed URLs, log rotation, and recursive promotion-condition handling are hardened. Invalid legacy non-JSON promotion conditions produce a recoverable error.
* Stored upload passwords are masked before form serialization. A failed save requires re-entry of a new or changed password. Null URL parameters no longer fail previews under PHP 8.4, and Test Now submits without an unintended second navigation.

See the [complete changelog](../../CHANGELOG.md) for individual corrections and regression evidence.

## Upgrade requirements

There is no new schema change or Composer platform requirement relative to 1.1.0. Magento Open Source 2.4.8 and 2.4.9 passed local acceptance. This platform compatibility does not make legacy editor customizations compatible automatically.

Before upgrading a representative staging copy:

1. Back up the matching database, code, Composer lock file, feed configuration, and output files. Pause schedules and uploads during comparison.
2. Migrate custom `prepare_form_*` observers, legacy tab plugins, and PHP/PHTML directive parameter renderers to UI data-provider modifiers or declarative components. The module's own six observers and two tab-visibility plugins are already replaced. Follow the [developer migration contract](../ui-component-editor.md#extending-the-editor).
3. Update downstream constructor overrides. `Ui/Component/Listing/Column/FeedActions` now receives `AuthorizationInterface`; custom `Composite` and `Configurable` product-adapter subclasses must forward the linked-product collection factory. Ordinary stores without these custom subclasses have no constructor migration to perform.
4. Review website/store overrides for microdata and Google Ads settings, and clear applicable caches. Existing overrides now take effect. New non-Google feeds default to microdata disabled; existing selections remain stored.
5. Rebuild DI and Admin static assets through the store's normal deployment process. Run `setup:upgrade`, particularly when upgrading from 1.0, which also needs the 1.1 schema changes.
6. Save and reopen a disabled copy of each important feed, then compare preview and complete output. Check currency, category IDs, promotion dates, null directive defaults, stock, prices, restricted roles, and masked uploads. Validate each actual recipient before resuming delivery.

**After 1.2.0 is published and indexed**, a Composer installation can upgrade with:

```bash
composer require 'mage-os/module-shopping-feed:^1.2' --no-update
composer update mage-os/module-shopping-feed --with-dependencies
bin/magento setup:upgrade
bin/magento cache:clean
```

For current source evaluation, use the reviewed commit from the release PR at `app/code/MageOS/ShoppingFeed` and record its full SHA. A draft release is not an installable Composer tag. The [installation guide](../wiki/Installation-and-Upgrade.md#upgrading-from-11-to-the-120-candidate) covers the complete sequence.

There is no old/new editor configuration switch. Restoring the prior package and rebuilding DI/static assets restores the previous editor. Restore matching configuration from backup when necessary; code rollback cannot recover promotion dates erased by an earlier development candidate or undo later saved configuration. No Rocket Web package data is migrated automatically.

## Verification and limits

The [October 3 local acceptance record](../reviews/2026-10-03-local-acceptance.md) covers runtime commit `133af71`:

* 809 unit tests on Magento 2.4.8, Magento 2.4.9, and Mage-OS 3.5.0; 21 official integration tests and production DI compilation on each Magento Docker profile.
* 29 frontend tests, 26 XML schema checks, actual-framework date/null-value cases, eight-preset browser/output comparisons, and six-role permission checks.
* Per Magento version: 26 semantic catalog scenarios, 15 native configurable MSI scenarios, pricing and store-scope checks, all eight presets at 5,000 synthetic products, two real hourly cron cycles, worker recovery, private FTP/SFTP delivery, and rollback rehearsals.
* Test fixtures removed and original data/output preserved. The shared Mage-OS installation retains Nebula disabled.

These are recorded local results, not proof that the release candidate's remote CI is green. Follow the [release preparation record](../reviews/2026-10-03-release-1.2.0-preparation.md) and the exact commit's [Actions results](https://github.com/mage-os-lab/module-shopping-feed/actions/workflows/ci.yml).

Remaining target checks include external provider ingestion, customer transfer destinations, consent-managed tag delivery, Varnish behavior, native Nebula UI Bridge rendering, original Rocket Web package coexistence, and representative production capacity. The synthetic volume run is not a hosting capacity promise. Coding-standard scans reported zero errors with existing warnings permitted by repository configuration; review their disposition before final release approval. Generated feed files remain public under the configured media path.

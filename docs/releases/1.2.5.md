# Mage-OS Shopping Feed 1.2.5

Release date: 2026-10-22.

Version 1.2.5 creates the **Skip from Being Submitted** product attribute that earlier releases checked but never created, and reads dropdown and multiselect option labels for the feed's store view.

## Upgrade requirements

**Run `setup:upgrade`.** It creates `mageos_shopping_feed_skip_submit` as a Yes/No product attribute, default No, with store-view scope, in the **Shopping Feed** group of every existing product attribute set. A merchant-created attribute with that code is kept unchanged, including its scope, labels, set assignments, and saved values. There are no table or column changes, and platform and Composer requirements are the same as 1.2.4.

Back up matching code, database, Composer lock file, and accepted feed files. Upgrade on staging, then compare a complete generated file per store view with the accepted output: dropdown and multiselect columns on non-default store views now carry that store view's option labels where an override exists.

```sh
composer require 'mage-os/module-shopping-feed:^1.2.5' --no-update
composer update mage-os/module-shopping-feed --with-dependencies
bin/magento setup:upgrade
bin/magento cache:clean
```

Follow the store's normal production compilation and static-content deployment process. Upgrading from 1.2.3 or earlier also requires the [1.2.4 SFTP host-key fingerprint step](1.2.4.md#upgrade-requirements). The created attribute and its saved values stay in the database after a code rollback, and 1.2.4 still honors a Yes value because it already checked the attribute.

## Fixed

- **Product exclusion.** `setup:upgrade` creates the **Skip from Being Submitted** field on the product form. Yes leaves the product, including configurable, grouped, and bundle children, out of every feed for that store view, and the feed log names it; a store-view No restores it there. The field is user-managed: deleting it in Admin disables the exclusion, and a later `setup:upgrade` does not recreate it ([#22](https://github.com/mage-os-lab/module-shopping-feed/issues/22)).
- **Store-view option labels.** Dropdown and multiselect columns use the feed store view's option labels and fall back to the admin label when no override exists. Labels are cached per store, so feeds for different store views in one cron run do not share labels. Option rows from custom source models without a usable value are skipped instead of failing generation ([#23](https://github.com/mage-os-lab/module-shopping-feed/issues/23)).

## Verification and limits

Local checks on the release candidate, on Mage-OS 3.6.0 with PHP 8.4.26 and the unit suite also on PHP 8.5.11: 951 unit tests with 2614 assertions, 38 integration tests with 133 assertions on a fresh install, four database persistence tests, 84 JavaScript checks, PHPStan level 8 with a baseline one entry smaller than 1.2.4, the Magento coding standard, and the Composer, wiki, and consolidation validators. The integration suite covers store-view exclusion on configurable children and the parent, core non-table option sources, attribute sets created after the upgrade, and patch re-application. Functional acceptance on an upgraded store copy covered real `setup:upgrade` and its repeat, the Admin product form with store-view overrides, Admin and CLI previews, and queued generation. See the [verification record](../reviews/2026-10-22-pr-24-verification.md) and the [product-attribute record](../reviews/2026-10-21-product-attributes-issues-22-23.md).

Known limits: the "rows skipped" count in the generation summary and feed grid covers validator-rejected rows and adapter failures, not products excluded by the new field; the feed log names those. Sources that ignore the attribute store, such as `country_of_manufacture`, keep the process locale's labels. The preset output-limit key mismatch from 1.2.4 remains; configure explicit **Limit column output** rows. Generated files remain publicly accessible under the configured media path; use public catalog data only.

Check the release commit's [CI results](https://github.com/mage-os-lab/module-shopping-feed/actions/workflows/check-extension.yaml) for the supported platform matrix. External recipient ingestion and production volume were not part of this run.

# Mage-OS Shopping Feed 1.2.1

Released 2026-10-04.

## Reported defects

- [#9: required custom-option prices](https://github.com/mage-os-lab/module-shopping-feed/issues/9). A free value remains the minimum in every value order. Percentage prices use Magento's option calculator with the child's base price, and an explicitly selected default takes precedence over non-default values. Required-option additions remain enabled; this release does not introduce a new pricing switch.
- [#10: backorder availability](https://github.com/mage-os-lab/module-shopping-feed/issues/10). The mapper reads the effective backorder setting, including Use Config Settings. Eligible configurable children produce `in_stock`, `backorder`, or `preorder` in that priority order. An explicitly out-of-stock parent remains out of stock. A later backordered MSI source cannot override an in-stock source. Local Inventory continues requiring actual source quantity.
- [#11: Page Builder descriptions](https://github.com/mage-os-lab/module-shopping-feed/issues/11). Raw and escaped tags and style/script content are removed before applying text limits. Two entity-decoding passes handle escaped HTML Code content and its nested entities. Literal comparisons, quotes, UTF-8, and feed delimiters retain regression coverage. The issue's follow-up about early length limits and double-encoded entities is included.

## Rocket Web migration companion

This release adds discovery for the separate `rocketweb/module-shopping-feed-migration-rocketweb` 1.0.0 launch. The main module suggests the companion without requiring it. The feed management screen links to installation instructions when legacy modules or tables are detected, or to the installed tool when the operator has its migration ACL.

The companion previews and explicitly imports legacy configuration into disabled destination feeds. Schedules and uploads are held until separately reviewed activation. It preserves encrypted receipts, rejects stale/duplicate requests, and limits automatic rollback to unchanged imports. It does not apply global settings, translate custom PHP, change recipient URLs, or run a migration during Composer installation.

The initial legacy baseline is Rocket Web Shopping Feeds/Google Shopping/Promotions 2.3.4 and Local Inventory 2.3.2, on the same Magento installation and encryption key. Existing-store customizations and recipient acceptance need their own staging validation. Keep legacy modules enabled during `setup:upgrade`; disabling their declarative schema can remove their tables.

Read the [migration guide](../wiki/Rocket-Web-Migration.md) and [companion instructions](https://github.com/rocketweb/module-shopping-feed-migration-rocketweb#installation). The companion is optional and has its own 1.0.0 release and installation process.

## Upgrade and validation

There is no new schema change or required dependency relative to 1.2.0. Use the normal Magento deployment process, rebuild the affected generated/static/cache assets, and regenerate comparison feeds on staging. Stores upgrading from 1.1 still need the [1.2.0 editor customization review](../wiki/Installation-and-Upgrade.md).

The 32 new regression cases first produced 22 assertion failures against the exact v1.2.0 runtime, then passed with the corrections. The local suite passed 846 tests on Mage-OS 3.5/PHP 8.5/PHPUnit 12 and Magento Open Source 2.4.8/PHP 8.4/PHPUnit 10. JavaScript checks passed 47 tests, including installed-framework form behavior. The [preparation record](../reviews/2026-10-03-release-1.2.1-preparation.md) records local commands, artifact hashes, companion checks, and acceptance limits. These are local results, not remote CI or existing-store acceptance.

CI and package publication are tracked independently from the local checks above. Current CI is linked from the repository badge; existing-store and recipient acceptance remain staging checks.

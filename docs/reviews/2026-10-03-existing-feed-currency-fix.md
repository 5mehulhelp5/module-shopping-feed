# Existing-feed currency correction

The final shared Mage-OS browser pass found that original feed 63 has a blank saved currency and previews four configurable children in USD, while the UI Component editor selected EUR. Saving without changing the field could therefore change the feed's prices and currency. Native Admin and cron probes confirmed the mismatch between the store's EUR default and the feed's effective USD currency.

The form provider now resolves an existing record's blank or missing currency through the same feed store used by generation. New feeds continue to use their store's default currency. Explicit saved currency choices remain unchanged. Saving a legacy blank value makes the displayed effective currency explicit; opening the editor alone does not write it. This changes one PHP provider method, with no schema, JavaScript, constructor, or Nebula-specific changes.

Four unit cases cover existing blank, existing missing, new blank, and explicit currency values. The two existing-record cases failed with EUR instead of USD before the repair. The native integration case also fails with EUR instead of USD when the original provider is mounted in the disposable test container. It exercises provider projection, the JSON form envelope, converter persistence, and reloading with differing default/effective currencies. The repaired suite passes 809 unit tests on Magento 2.4.8, Magento 2.4.9, and Mage-OS 3.5.0, plus 21 integration tests and 53 assertions on each Docker version. Commit `133af71` is deployed on `mageos-latest`. The original editor displays USD without a save; a disabled copy passes unchanged browser save/reopen and browser preview. All four configurable rows preserve prices and other values, apart from the existing clock-based sale-date fallback. The copy was removed and the original module rows/files/settings match their baseline. See the [local acceptance record](2026-10-03-local-acceptance.md) for the complete deployment and preservation evidence.

The [October 2 deployment report](2026-10-02-mageos-latest-deployment-acceptance.md) originally treated the first fixture's currency change as setup. The original-feed reproduction corrects that interpretation. Previously saved explicit currency selections cannot be inferred or silently reversed by this fix.

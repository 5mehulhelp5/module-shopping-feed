# Mage-OS 3.5 local installation and acceptance, 2026-09-25

Follow-up: the Nebula compatibility, grouping-default, and indexer issues recorded below were subsequently addressed in the [Admin compatibility acceptance report](2026-09-25-admin-compatibility.md). This report preserves the earlier acceptance state.

The review-fix candidate was installed into the existing local Mage-OS 3.5 instance and tested against its real application, database, Admin, and Hyva storefront. Automated suites and the functional checks below passed. **Nebula Admin 0.9 remains incompatible with this module's legacy grid and forms.** Magento's standard Admin passed the tested workflows. This is a local acceptance record, not a completed production release gate.

## Additional defects found and fixed during acceptance

* Disabled feeds could still be queued by the scheduler. They are now skipped.
* Editing a schedule hour passed `-1 day` to Magento's locale date parser and threw an exception. The code now modifies a constructed date object.
* Local Inventory exported disabled MSI sources and could fall back to an unscoped row when no source qualified. Only enabled sources linked to the stock are exported; an empty MSI result stays empty.
* Repeated Admin saves could replace missing optional attribute mappings, such as `pattern`, `gender`, and `age_group`, with another row's parameters. Shared directive defaults no longer inherit a row's saved parameters, and missing saved attribute codes remain literal selectable values in that row. Two consecutive browser saves preserved the mappings.

These changes are additional to the fixes documented in [the review disposition](2026-09-24-review-fixes.md). Scheduler and disabled-source regressions were observed before their corrections. New unit and JavaScript regressions cover the affected behavior.

## Remaining limits and failed acceptance surfaces

* **Nebula Admin 0.9:** the installed theme replaces the JavaScript stack used by this module. The feed grid renders empty and legacy editing controls fail. The original Nebula modules were restored after standard-Admin testing, so this limitation remains in the local instance. See `nebula-admin.png` and `nebula-compatibility.json`. Resolving it requires an Admin integration, beyond the bounded fixes above.
* The default Google `item_group_id` parameter is the legacy value `0`. The generator treats it as parent SKU, while the standard-Admin selector has no `0` option and saves its first option, parent entity ID. Both outputs are valid grouping values, but the first save can change grouping identity. This additional mapping inconsistency remains open; it is separate from the optional-attribute corruption fixed above.
* The instance already had `catalogrule_rule`, `catalog_product_price`, and `catalogsearch_fulltext` indexers marked working before installation. Their prior state is present in the database backup; they remain a separate environment issue. No claim of a clean full reindex is made.
* The tests cover the default store and targeted MSI fixtures, not a full-volume export of the 43,186-product multi-store catalog, a cron soak, multiple application hosts, or an exhaustive pricing/backorder/source-status matrix.
* Standard-Admin restricted-role browser flows, clone/delete/mass-action controls, all optional configuration widgets, and every product-type combination were not exhaustively exercised.
* The Hyva metadata checks establish feed selection and emitted values. They do not certify every theme's native schema replacement or Google Ads event delivery.
* No Merchant Center ingestion, external destination, production scheduler, different PHP/platform matrix, original Rocket Web coexistence, or live customer order was tested. The complete [production acceptance plan](../../ACCEPTANCE-TEST-PLAN.md) remains a separate release gate.

## Cleanup and rollback

Only the synthetic acceptance feeds (69 through 72), their generated public files and children, and the temporary Admin account were removed. Generated files and probe scripts were retained in the private evidence directory. Temporary MSI sources, rules, reservations, and integration records were rolled back. The original feed 63 remains, with no upload destinations, schedules, or queue rows. Original microdata settings, forced two-factor provider configuration, and all Nebula module states were restored. Temporary credential files, browser sessions, the transfer server, and the disposable database were removed or stopped. The local Mage-OS services remain available.

The unrelated setup additions were handled separately. The 25 new tables were moved intact to `shopping_feed_setup_quarantine_20260925`. Exactly 45 new setup rows were removed from shared tables after matching their identities and full contents against the captured preview and proving their absence from the original backup. This removed only new attribute definitions, their mappings, the placeholder `company-terms` page and its URLs, and Orangecat setup records. No customer or product values existed for the two new attributes. Two empty Admin columns and one newly derived customer-grid column were removed. Checksums for all 12 affected shared tables match the original backup. The quarantine, `database-before-unrelated-cleanup.sql.gz`, and `undo-setup-cleanup.sql` preserve the inverse operation. Routine access logs, cron history, visitor records, and indexer bookkeeping from running the local instance were retained.

Rollback material in the evidence directory:

* `module-before.tar.gz`: prior installed code.
* `database-before.sql.gz`: checked full database backup, containing private local data.
* `config-before.php`, `config-before-stock-admin.php`, and `hyva-themes-before.json`: original application configuration.
* `schema-preview.sql`, `cleanup-results.json`, and `final-candidate-manifest.json`: exact schema delta, cleanup state, and installed file identity.
* `setup-cleanup-preview.json`, `setup-cleanup-results.json`, and `database-comparison.json`: guarded rollback and final comparison of the unrelated setup additions. The original declarative SQL preview alone was insufficient to predict these side effects.

For a code rollback, first stop this module's workers and local HTTP traffic, preserve the candidate directory under a new name, restore the module archive to its recorded path, regenerate DI, and clean caches. Keep the widened password column as `text`; shrinking it can truncate encrypted credentials. A full database restore is an independent, destructive operation and is unnecessary for that code rollback. Preserve current data and obtain explicit approval before restoring the full backup. Do not overwrite unrelated application configuration with the saved files.

Installed integration reproduction uses the archived `probes/shopping-feed-integration-bootstrap-20260925.php` with `vendor/bin/phpunit --no-configuration --bootstrap <bootstrap> app/code/MageOS/ShoppingFeed/Test/Integration`. Other application probes create temporary fixtures or expect the now-removed acceptance records; inspect their setup and cleanup before rerunning them. Normal automated suite commands are documented in the preceding review record and the development wiki.
